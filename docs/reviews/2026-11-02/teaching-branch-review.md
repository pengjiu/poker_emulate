## Standards：项目规范

**发现并修复：可确认的内部证据软链接无法可靠便携导出。**

原验证通过 `realpath` 接受指向工程内部文件的软链接；导出时 `fs.cp` 又将它转成指向原工程的绝对链接。导出后的工程立即出现 `EVIDENCE_PATH`，移动原工程后还会失去依据文件。

修复统一了证据入口与便携契约：确认和媒体验证共用的检查逐层要求真实目录、最终普通文件，工程根之下任何符号链接均返回 `EVIDENCE_PATH`。工程根本身可以经链接访问。没有对整个 evidence 目录启用无条件跟随链接的复制，也没有静默接受新文件内容。技能参考与中文、英文、日文错误提示同步更新。

其他规范检查：牌局重放和金额计算继续使用唯一规则引擎；表现仍进入同一 Compiler 与共享 renderer；编辑仍通过带修订号和回执的原子提交；v2 工程使用可选扩展；未新增依赖或 GitHub Actions。局部紧凑编码风格不作为阻断项。

### 分支复制如何保留可信状态

`branch.put` 的 `copyFrom:{branchId,beatId}` 只复制原分支到指定 beat 的前缀，要求相同主线起点与新的分支 ID。追加动作仍由现有引擎验证。生成的 beat/analysis ID 冲突、无效截止点或错误起点都会使整批编辑回滚。

只复制前缀已引用、且节点也位于该前缀的分析；资料改名与节点映射由运行时完成。原 `materialHash` 有效且新决策指纹等于旧 `decisionHash` 时，才更新改名后的资料指纹。未复核或已失效的资料仍保持原状态；`evidenceHash` 保留原字节绑定，不重新读取文件来自动确认。浏览器和 Agent 均不填写哈希。
