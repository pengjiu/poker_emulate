# 声音、章节复用与成套交付

所有操作仍经过项目存储、六方法和单一 Compiler。视频预览与输出共用客户端；音频预听与编码使用相同的来源校验和 FFmpeg 混合图。该文档补充既有语音契约，不引入另一种工程格式。

## 声音设置

`apply` 中的 `sound.set` 不指定片段时替换项目 `sound`，指定 `sceneId` 和 `beatId` 时替换该片段的 `sound`。未修改字段应从当前设置保留。项目设置是以下可选字段：

| 字段 | 含义与边界 |
| --- | --- |
| `effects` | `{enabled:boolean,volume?:0..1}`；按照实际发牌、下注、归池、结算事件生成短音效 |
| `bed` | `{assetId,volume?:0..1,start?:seconds,loop?:boolean}`；`start` 是背景音进入节目时间 |
| `voiceGainDB` | 口播增益，−24 至 +12 dB |
| `ducking` | `{enabled?,reductionDB?:0..30,attack?:0.001..1,release?:0.01..3}`；口播期间降低非口播声源 |
| `loudness` | `{integrated:-30..-10,truePeak:-6..-1,range?:1..20}`；目标分别为 LUFS、dBTP、LU |

`sound.bed` 使用与 `audio.attach` 相同的 `source:{path}` 或 `source:{data}` 导入实测音频，`value` 可指定 `volume/start/loop`。系统记录资产内容与时长；`source:null` 移除背景音。直接填入未导入的资产 ID 会阻止制作。

片段设置为 `{quiet?:boolean,effects?:[{kind,at,volume?}]}`。`kind` 为 `deal/bet/collect/payout`，`at` 相对该片段的起点，必须落在该片段内。片段改短后越界提示不能悄悄流入下一段。`quiet:true` 抑制该区间的所有非口播声音，适合真正的思考留白；口播应在另一个片段结束后再开始留白。

内置音效是短、确定性的本地合成音效，不会冒充人声。混合时先统一采样率并按编译时钟放置来源，再做压低背景、静音区间和响度处理。回执记录实际编码输出的测量结果；响度目标不能代替口播表演、术语发音或长期听感审查。

## 排演时长与正式配音

`beat.rehearsalDuration` 是按语言记录的阅读时间估计，例如 `{"zh-CN":18,"en-US":22,"ja-JP":25}`，每项必须为正数且不超过一天。没有音频时，它决定该语言旁白的排演时长。真实音频到位后，实测时长覆盖估计，普通 `hold` 仍是最短停留；不要把旧的长阅读估计写进 `hold`。

该语言没有音频引用且有明确的正数估计时，可通过 `timing.set`、`captions.set` 和 `presentation.cues` 确认未配音排演时间表。命令自动记录 `audioHash:null`（动作时序存入 `timing.audioHashes[locale]`）；未提供绑定、旧的非空音频哈希、缺少该语言估计和空精确字幕都不能冒充已确认的排演。三类时间表继续使用同一旁白时钟，精确字幕和表现提示点相对旁白起点；动作时点相对片段起点。字幕仍须保留完整讲稿、每条覆盖可见帧，且不能超出估计的旁白时长。表现提示点 `cues:[]` 仍表示清空该语言的事件，不需要时间绑定。

实际音频的变更继续使依赖它的字幕、动作时序和表现提示点失效，需要明确重新确认。排演估计不是音频时长，也不能作为已审听的依据。

首次生成或导入实际音频也会使这三类空绑定失效；`--rehearsal` 不绕过这些失效问题。审听后重新提交对应公开命令，系统才会绑定到当前实测音频。排演草稿始终保留 `AUDIO_MISSING`，不能作为正式配音输出。

正式 `render` 和 `produce` 必须通过全部阻断检查。用户允许延后配音时可显式加 `--rehearsal`；此模式只放行 `AUDIO_MISSING`，成片带可见的待配音标记，回执为 `VISUAL_PASS` 并列出未配音段落。`AUDIO_STALE`、依据失配、非法行动、缺失对象和时间绑定失效均仍然阻止输出。

## 输出编排

`delivery.set` 接受完整列表 `[{id,title,output}]`，保存在可选的项目 `deliverables`。`title` 是语言映射，`output` 与普通 `output.set` 使用同一格式。文件名 ID 限于 1–80 个字母、数字、下划线或连字符。

每个输出可使用不同语言、横竖画幅、质量、字幕及 `sequence`。序列项为 `{id,sceneId,branchId?,fromBeatId?,toBeatId?}`。短片从中间片段开始时，Compiler 先重放前面的合法行动，保留真实状态，再重新计算节选时钟。片段末尾以后的无关草稿不阻止当前节选；当前节选实际引用的分析、回放或对照仍须有效。

```sh
node bin/river.mjs produce --project projects/course --out artifacts/course --only ep1-wide,ep1-tall
node bin/river.mjs produce --project projects/course --out artifacts/course --rehearsal
```

批量制作先复制一个不可变的便携项目快照，后续本地编辑不会混入正在制作的版本。交付目录包括每个输出的 MP4、SRT（启用字幕时）、讲稿时间段、章节、渲染回执；还包括所有选定语言的练习页面、`index.html`、`delivery.json` 和完整可编辑 `project/`（含资产与依据）。未选语言不强制生成练习。`practice.html` 是选定语言中的默认入口。

`delivery.json` 明确列出各版本状态、未配音片段、资产内容哈希和练习入口。重复执行会检查现有文件与回执，损坏或被修改的旧交付不算缓存命中。取消和失败清理未完成的暂存目录，不删除已完成交付。

## 章节缓存与失效

章节按选定序列项划分，单路线也可成为一个章节。每个章节的本地时间、可见牌局、图层、字幕、镜头和尺寸决定其视觉身份；无关场景标题、课程顺序变化不会使未改章节失效。媒体实现、客户端构建和编码工具参数也参与身份。

章节键及回执另外记录 `visualImplementationHash`，由捕获/编码实现与章节编排实现生成。即使计划、客户端和工具链未变，捕获实现升级也会重制章节；混音模块变化只使最终媒体失效。对整个捕获文件取哈希会保守重制，但不需要维护容易遗漏的手工版本号。

先复用经身份与字节校验的章节画面，再按当前顺序合并，最后按整段编译时间线混音并写字幕和章节索引。换一句配音如果改变了时长、字幕或提示点，只能复用仍相同的章节；声音与画面不会因为缓存而沿用旧时间。破损的章节、字幕、关键帧、项目或依据均被拒绝，不能静默继续使用。

导演台播放含声音后期的工程时，会准备同一份混合音轨；改变布局且没有改变声音内容可复用它。预听缓存每次先核对源音频，不能借旧缓存掩盖被修改的资产。实际播放器的连续性和输出编码帧仍需要媒体回归验证。
