最终选择：沿用现有 JavaScript、规则实现、客户端视觉和浏览器渲染方式，交付一个**本地运行、Agent 优先、项目可迁移、成片可复现的德州扑克内容制作工具**。先消除会改错内容、丢失任务或产生错误成片的缺口，再精修操作与视频表现。M1–M8 已依此完成，未扩大首版产品范围。

这里的“帕累托最优”指在本节明确的需求、成本和候选路线内，选择没有发现被其他路线全面支配的方案。工作量和性能目标属于计划值，尚不能作为数学上的全局最优证明或实施成绩。

## 1. 交付目标与取舍

一次标准任务为：Agent 收到场景与教学意图 → 按 skill 编排牌局和讲稿 → 使用外部 TTS 或本地语音模型 → 导入音频 → 校验 → 预览 → 导出 MP4、字幕、完整项目和回执。期间不依赖人工点界面、手动搬音频或修改源代码。

### 必须同时达到的结果

| 维度 | 首版交付标准 |
| --- | --- |
| 场景表达 | 标准无限注德州，2–9 人，任一街开始；可设合法底牌、公共牌、筹码、已有投入、行动顺序；支持主线和一层替代路线 |
| 内容自由度 | 自由旁白、先讲后行动、行动后讲解、选定座位亮牌；入门、策略与剥削讲解共用一套场景格式 |
| Agent 操作 | 维持五个编辑方法；读取合法动作，批量编辑，明确错误定位，安全重试；完整任务可保存、恢复和迁移 |
| 语言 | 首发简体中文、英文、日文；界面、片段文案、旁白和可选字幕一致；新增语言通过字典与内容扩展 |
| 画幅 | 16:9 横版与 9:16 竖版分别布局；输出草稿 720p/24 fps，正式预设 1080p/30 fps |
| 客户端观感 | 连续的发牌、下注、跟注、收池与摊牌过程；牌面、底池、行动者和筹码可读；成片无导演台控件及教学标签 |
| 语音 | 平台消费外部音频，负责导入、时长探测、失效判断和同步；TTS 供应商选择与合成留在 Agent 工作流 |
| 可信交付 | 发布结果绑定项目、路线、语言、画幅、资源和运行时指纹；失败不覆盖已有成片，不返回伪成功 |

首版范围止于单机制作。实时多人、充值支付、云队列、团队协作、内置语音模型、内置 GTO 求解器、ICM 计算、多次发牌、自动抽水、多层分支和通用视频编辑器留到独立需求出现时再评估。现有牌局快照可以表达的教学内容继续允许，不把教学主题做成有限模板菜单。

### 候选路线比较

| 路线 | 相对改动与成本 | 对核心需求的影响 | 决定 |
| --- | --- | --- | --- |
| A 保留原型，只优化外观 | 低 | 无法通过保存恢复、音频迁移、误编辑和失败恢复门槛 | 淘汰 |
| B 保留技术栈，补齐本地制作闭环 | 中 | 覆盖全部首版目标；复用已验证的牌桌和规则 | **执行** |
| C 重写为通用剪辑与动画平台 | 高 | 可能增加复杂时间线能力；增加迁移和验证工作，首版不需要这些能力 | 延后 |
| D 同时建设云端多人制作平台 | 很高 | 增加账户、服务部署和调度职责，当前无人值守制作仍需先完成 B | 延后 |

判断顺序为：正确性与任务可恢复是硬门槛；通过后比较 Agent 学习负担、成片质量、维护成本和实施量。B 以五个方法、一个项目格式、一个规则实现和一个画面 renderer 完成所需能力。对当前范围，尚无证据表明 C/D 的新增成本能减少 B 中必须完成的工作。不给候选方案编造精确收益分数。

### 代码审阅发现的交付风险

以下是静态审阅结论，未执行进程故障注入，不能与上述动态复现混称：

- **导出提交缺少隔离。** `render.mjs:21,29,43–51` 从最终路径推导共享临时文件，使用覆盖写入；没有完整的任务锁、超时、取消及子进程退出协议。回执缺少分支、项目指纹和成片校验摘要。由 M5 处理。
- **规则存在两份执行载体。** Node 读取当前源码，浏览器读取预先内嵌在 `index.html` 的代码。本轮两者内容匹配，但未来改源码漏构建时没有阻止导出。由 M4/M5 让浏览器只消费同一份已编译画面计划，并校验构建指纹。
- **规则证据仍有自洽性限制。** 随机模拟从同一引擎给出的合法动作中采样，不能发现所有合法动作集合错误。由 M3/M8 增加独立预期值、无效快照及故障恢复用例。

已有价值保留：整数筹码、单一转移函数、主池边池计算、同会话幂等、外部音频、横竖版座位布局和简洁三块导演台。重构围绕上述具体缺口进行，不以换框架或扩大文件数量作为完成标准。

## 3. 精修后的职责与数据约定

### 单一职责分配

下列目录已经建立。`prototype/` 的重复执行代码已移入只读归档，原课件、音频和历史样片保留。

| 责任模块 | 目标位置 | 唯一负责的内容 |
| --- | --- | --- |
| Project | `src/project/` | 项目格式、迁移、资源目录、原子保存、修订号、请求回执 |
| Poker | `src/poker/` | 快照合法性、行动权、下注、边池、退回、摊牌；纯状态转移 |
| Director | `src/director.mjs` | 五个方法、编辑批次与选中场景；调用 Project/Poker，不重复计算筹码 |
| Compiler | `src/compiler.mjs` | 路线选择、规则执行、逐动作状态、语言与时序，生成 RenderPlan |
| Media | `src/media/` | 音频探测与导入、预检、受控渲染、成片验证与提交 |
| Client / Studio | `src/client/`、`src/studio/` | Client 按 RenderPlan 和时间绘制；Studio 展示状态与编辑，不产生第二套规则 |
| 适配入口 | `bin/river.mjs`、本地预览入口 | CLI/NDJSON 与浏览器连接同一 Director；只做输入输出适配 |

每个实施步骤指定一名执行 Owner；即使后来安排多人，同一模块同时只有一名写入者。Project 是持久化的唯一写入责任方。单机运行保持一个活动写入进程；浏览器与 Agent 的修改经过该进程和修订校验，不各存一份课件。

本地运行时监听回环地址，stdio/NDJSON 与浏览器请求调用同一个 Director。现有静态预览服务器演进为这一入口，首版无需另建远端控制服务。`observe` 返回当前预览地址与修订，Agent 的标准制作流程继续走结构化请求。

### 项目与资源

项目以可复制的目录为规范形式：`project.json + assets/ + evidence/`。压缩包是传输封装，不另建格式。`artifacts/` 存成片，不参与可编辑源数据的哈希。

`project.json` 使用 `format: river.project`、`version: 2`，包含：项目 ID、修订号、`lesson.scenes`、所选输出、资源索引和最近请求回执。输出记录语言、画幅、分辨率预设、场景、路线、字幕策略。播放头与面板折叠状态属于可丢弃视图状态，不能改变牌局或输出选择。

音频导入后按内容哈希存入 `assets/`；片段引用资源 ID，不保存调用机器的绝对路径、blob URL 或临时文件位置。导入负责探测媒体，不再要求 Agent 手填时长；保存内容哈希、实际时长、语言和对应旁白文本哈希。相同内容复用同一资源。

旧版 v1 JSON 显式迁移为新目录并产生迁移回执，原文件和音频不覆盖。历史输出选择本来就未保存，迁移不能推断：调用方显式指定，或迁移回执清楚列出采用的默认值。旧版不进入长期双格式执行分支。

### 五个方法保持稳定

| 方法 | 约定 |
| --- | --- |
| `load` | 打开项目并恢复保存的修订与输出；验证结构，返回诊断。加载本身不伪造一次编辑 |
| `observe` | 返回修订、选中路线/片段、以 BB 表示的状态、合法动作及当前输出就绪问题；玩家视角只含此刻可见信息 |
| `apply` | 接受非空原子批次，要求 `requestId + expectedRevision`；成功持久化后才返回成功回执 |
| `seek` | 在选定路线定位片段；未知 ID 报错，定位不改变课件、筹码或修订 |
| `export` | 输出完整可迁移项目或不可变 RenderPlan；成片由同一运行时的 `render` 命令消费该快照 |

保留 `output.set / scene.put / branch.put / narration.set / audio.attach` 五种编辑命令。`scene.put` 保留全量场景表达能力；不为每个位置、牌型和教学主题增加专用方法。`audio.attach` 接收本地文件或浏览器导入内容，经 Project/Media 导入后再原子关联。

错误统一包含 `code、path、message、retryable`，必要时附合法动作或当前修订。CLI 未知选项、字段或缺参非零退出；交互 NDJSON 会话逐请求返回成功/失败，批处理结束时只要有拒绝即非零退出，批处理调用方也能正确判断。

持久化采用临时文件、刷盘、原子替换；修订与回执写在同一次提交里。仅保留最近 128 个成功请求回执。窗口内完全相同的重试返回原回执；不同内容复用 ID 拒绝；超出窗口的旧修订请求明确拒绝，不自动重演。进程退出后重新打开项目仍遵守这一约定。首先实现单写入锁，不引入数据库和第二个事件执行核心。

### 验证范围与草稿

- **结构检查**面向全项目：字段类型、版本、引用与唯一 ID。场景内所有主线/分支片段 ID 唯一，场景 ID 在项目内唯一，分支 ID 在场景内唯一。结构有歧义则拒绝写入。
- **规则检查**针对待编辑/所选路线：完整起始状态及行动必须合法。写入某条路线时检查受该修改影响的全部路线；主线共享前缀改变时检查其下游分支。其他未受影响路线已有的问题独立列出。
- **草稿允许缺翻译和音频**，保存与诊断可继续；缺失字段不等于空字符串已完成。合法但不完整的草稿显示就绪问题，不产生可交付成片。
- **成片预检**只针对明确选择的场景、路线、语言和预设：每个可见文本有对应语言，每段旁白有匹配的可解码音频，资源哈希/文本哈希正确，行动合法，输出设置完整。全项目检查另行列出各输出组合状态。

关闭回合的快照必须满足无需任何仍可行动玩家补足下注的条件；不一致时拒绝并定位。未知历史不能由 Agent 编造，skill 引导其从更早的明确状态开始。用户输入和规则计算使用 BB，内部继续整数最小筹码；输入数值及聚合必须在安全整数范围内。

### 编排与成片

Compiler 先选定“主线前缀 + 分支续段”，再执行一次规则。多动作片段展开为逐动作子段，保存每一步状态，不跳过中间行动。默认动作完成后开始该片段旁白；先讲后行动用空动作片段表达，保持已有使用方式。

RenderPlan 固定行动状态、可见牌、语言、布局、音频起点和整帧时序。旁白段覆盖完整音频并留 0.35 秒尾段；字幕仅覆盖实际旁白时间。预览与导出共同使用 `renderFrame(plan, frameIndex)`，筹码、牌面及动画不依赖墙钟、随机数或未来未公开底牌。帧宽高按预设传入，横竖版按相同状态重排。

Client 使用虚构桌名与玩家，可配置名称、头像和桌布色；保持一个完成度高的默认主题。首版不做主题市场。导演台保留牌桌、片段条和一个上下文编辑区；顶部集中项目、场景/路线、语言、画幅及保存/导出状态。平时隐藏完整 JSON，复杂快照仍可导入。播放中发生编辑先暂停，再以新修订重新定位，避免视图混入旧时间线。

语音调用留给 skill 及外部工具。原型中的系统语音可继续作为无外部账户的验证来源；平台不新增供应商设置大厅。新语种增加 locale 字典、翻译和音频，无需修改扑克规则。GTO 定量讲解须由 Agent 提供与场景相符、可复核的求解或解析推导材料；剥削讲解保留对手假设。场景脚本不承担证明策略最优的职责。

编排可读取导演观察；第一视角讲稿依据当前玩家观察与已发生历史。未来公共牌、未亮出的对手牌不得提前写进该时刻的决策理由。需要讲解全局牌力时，在独立片段明确执行亮牌提示，再使用相应信息。

## 6. 渲染运行与交付约定

单机默认一次只运行一个渲染任务。输入在提交时冻结，指纹覆盖项目内容、所选路线、输出预设、音频哈希、字典、字体与 renderer/toolchain 版本。成片期间继续编辑只能影响下一任务。任务记录明确的时间、内存和临时目录限额；默认超时为 `max(120 秒, 片长 × 10)`、上限 2 小时，RSS 上限 3 GiB、临时目录上限 1 GiB。超过限额停止并诊断，不自动扩大预算；A16 使用固定 60 秒课件与 600 秒上限。

每个任务写独立暂存目录。依次完成：预检 → 视频帧与音轨合成 → 解码/规格校验 → 关键帧/同步检查 → 写回执 → 原子发布整个结果目录。正式结果为：

```text
artifacts/<job-id>/
  video.mp4
  captions.srt             # 有旁白时产生
  receipt.json
  validation.json
  frames/                 # 有限数量的验收关键帧
```

失败写 `failure.json`，包含失败阶段、错误码、输入指纹、是否可重试与最多 2 MiB 日志。失败不产生成功目录；清理浏览器、FFmpeg、管道和暂存媒体。已有成功目录只在指纹和媒体校验均匹配时复用，内容不同则生成新目录。首版失败后整任务重试，不实现断点续帧和分布式队列。

`receipt.json` 必须包括项目 ID/修订/哈希、场景、分支、语言、画幅、分辨率、帧率、帧数、时长、资源哈希、RenderPlan 哈希、工具链版本、MP4 哈希及校验结果。只有结果目录完成发布且全部强制校验通过，才返回成功。

A16 已实测通过：60 秒正式视频总墙钟 382.853 秒，独立采样的任务进程树峰值 RSS 1,552,498,688 字节，暂存峰值 16,822,397 字节；详见固定运行 `performance/report.json`。当前参考环境为 Apple M4 Pro、48 GiB、macOS 26.6.2、Node v24.22.1、FFmpeg/ffprobe 8.1.1；验收同时记录实际浏览器、Playwright 和字体版本。统计整个任务进程树，计时从提交到成功发布。最多额外进行两轮针对已定位瓶颈的优化；不达标则 A16 保持 FAIL，不通过降低正式输出质量伪装达标。

正式验收按结构/规则/接口 → 音频/时序 → 少量代表场景渲染 → 完整矩阵的顺序。前置失败时停止后续昂贵渲染，保留本次结果，避免反复批量导出掩盖问题。
