# 国际与日语扑克讲解机制调研

检索日期：2026-11-02（Asia/Shanghai）。用途：为 River Studio 的 Agent 可选讲解模式提供一手依据和验收标准。本文是样本研究，不能推出全平台风格排名、完播率或学习效果的因果结论。

## 结论与证据范围

应把模式定义为可组合的讲解机制，而非模仿某位创作者的人设、原声或口头禅。样本反复出现的机制包括：个人决策跟随、悬念后复盘、提问后揭晓、逐街纠错、假设与数据检验、条件化剥削、赛事报动作与解释分工、多手主题串联。下文将其收敛为 10 个可组合 recipe；“短视频”主要改变节奏和取舍，不宜另立知识模式。

本轮登记 16 个具体公开样本，涉及 Brad Owen、Andrew Neeme、Doug Polk / Upswing、Nick Petrangelo / Upswing、Jonathan Little、GTO Wizard、WPT Raw Deal、PokerStars 以及世界のヨコサワ。材料分为：

- **A：正文**——已读取作者或官方发布的文字正文，足以核对其论证结构；不等于听过对应视频的完整口播。
- **B：官方说明**——已读取节目官方简介或活动说明；只能确认被明确说明的节目机制，不能判断实际音色、停顿、语速和完整推理。
- **C：官方目录**——只能确认样本存在、作者、题材或自述；不得从标题推断已发生的具体口播。
- **A-index：正文索引**——可读取一手正文的检索索引片段；后续原页访问失败，证据弱于完整 A。

没有登录平台，没有批量下载视频，没有完整听看全部视频，也没有获得创作者后台的完播、留存或转化数据。资料中出现的策略结论属于该作者在对应假设下的分析，不能自动继承为本项目任意场景的 GTO 证据。

## 模式归纳：10 个可组合 recipe

以下是本研究的抽象建议，不是源作者自称的分类。一个视频可以主模式固定，某个章节明确切到另一机制；不能靠每句随机切换风格。

| 模式 | 核心机制 / 参考样本 | 模式一致性的最小验收 |
| --- | --- | --- |
| 跟打思考 | 决策当下的可见信息→关键顾虑→选择→行动后更新；G05、G01 的个人线。 | 固定主角；揭牌前不引用对手真牌或未来牌；每个关键决策有当下理由；旁白能连续跨行动。 |

| 决策竞猜 | 提问→留真实思考间隔→公布选项 / 答案→解释与边界；G07、G15。 | 答案在问题后；思考期间没有提前揭牌 / 结果字幕；正确答案有依据，可承认近似或混合策略。 |

## 最小维度与风格快照

为使模式既稳定又不限制想象力，建议只保持少量正交维度。下面是语义建议，不要求逐字采用字段名，也不建议再建第二套导演执行器。

1. **叙述角色与信息边界**：主角是谁、第一人称 / 外部观察 / 事后分析；哪些牌在什么时候已知。第一人称与 cards-down 不是同一个字段；外部解说也可能不知道底牌。
2. **推理组织**：跟决策、悬念揭晓、提问揭晓、假设实验、条件调整、对照纠错。允许多种组合，指定主结构与局部覆盖。
3. **信息密度与时序**：关键 / 次要决策的解释深度，动作前 / 动作中 / 动作后讲解、思考留白、是否跨手。快慢不能只靠 TTS speed。
4. **表达与声音**：正式程度、术语目标人群、幽默密度、情绪曲线、speaker / voice；中文、英文、日文分别依据本地惯用表达。不要把“专业”硬编码为句句有术语或没有情绪。
5. **呈现结构**：单手 / 多例 / 连续牌局、对照顺序、可选分析材料。横竖屏是输出适配；桌型、人数、街道、深度是场景标签，不是风格硬限制。

一次生成应冻结“模式 ID / 版本 + 已解析维度 + 内容目标 + 本地化策略 + 局部覆盖”。验收读取这份实际快照，避免事后目录修改导致旧视频无法解释。Agent 可以给出新模式或自定义维度；系统只验证结构、信息一致性与支持的能力，不应机械拦截新话术或规定所有视频必须同样开头、同样字数。

## 可执行验收建议

自动检查用于确认可证明的结构事实；专家审读和听音用于确认自然度，二者不能互相替代。建议使用同一组合法牌局测试不同模式，而不是每个模式都另选一手更戏剧化的牌来掩盖差异。

| 验收项 | 可接受证据 | 不足以验收的替代品 |
| --- | --- | --- |
| 风格可重放 | 相同模式版本与覆盖能解析为一致快照；自定义模式也能 observe / validate / export。 | 只有 UI 下拉框，输出和验收读取不到选择。 |
| 跟打与信息纪律 | 6 人桌翻前完整顺序→翻后 2 人→持续固定 Hero；在每个分析节点核对只使用当时已知牌、行动与假设。 | 最后画面像 6 人桌，但脚本提前知道对手底牌。 |
| 旁白跟动作 | 一段有音频的旁白跨至少两个动作，播放器不中断 / 不从头开始，字幕时间不重叠失配；导出同样通过。 | 只在动作后的静帧播旁白，或只有静态计划结构测试。 |
| 竞猜机制 | 问题→可测静默→答案三段；答案出现前画面、字幕、音频均未泄露，能 seek 回放。 | 给问题和答案换标题，但都已显示在同一画面。 |
| 多手主题 | 至少两手不同人数 / 深度，输出为一个视频；顺序、换手状态、旁白接续和结尾总结可核对。 | 只有两份独立 MP4 或 scenes 数组。 |
| 对照机制 | 同一决策展示实际线和备选线，且起点 / 变更条件有记录；牌与筹码不串线。 | 两手不同牌，没有说明哪一项条件改变。 |
| 双声机制 | 两个 speaker 按脚本交替，各自声音保持稳定；预览 / 导出均可听出归属。 | 同一旁白改两个语气，或只生成两个未使用的音频文件。 |
| 推理有依据 | 所有定量 GTO 结论匹配本场景证据；剥削结论标明对手假设；允许弃牌、失败结果和被推翻假设。 | 术语多、引了大 V、结果赢了，便称 GTO。 |
| 风格清晰且自然 | 目标语言熟悉扑克的审读者能认出主要组织方式；随机抽 3 处关键决定能说清“为何”；听音无显著机械重复、断句不清或同情绪贯穿。记录人工判断。 | 关键词次数或模型自评“像专家、无 AI 味”。 |
| 版式与语言一致 | 同一模式至少中 / 英 / 日中已实现语言的脚本与界面一致；横竖屏关键数值和动作不丢。 | 仅切换按钮文本或仅跑编译成功。 |

首轮优先闭合“跟打思考、竞猜、条件剥削、对照纠错、主题多例”及共用播放能力，可覆盖大多数机制。深度范围图、多声道串场等扩展按实际支持程度标记，不宜为追求目录齐全虚构已实现能力。所有模式始终依赖同一合法牌局、同一视角处理和同一导出计划。
